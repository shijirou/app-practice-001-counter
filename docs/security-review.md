# セキュリティチェックの記録

## 2026-11-14 1回目（カウンターアプリ全体）

### 結論
**今すぐ直す必要のある問題は 0 件。** 気をつける点（公開するときに対応）が 3 件ある。
このアプリは、サーバー・DB・ログイン・外部通信がなく、データはブラウザの localStorage に入るだけなので、攻撃を受ける入口がもともと少ない。

調べた範囲: このパソコン内のコード・設定と、GitHub 上のリポジトリ設定。外部への攻撃的なテストはしていない。
なお、公式の `/security-review` は「未マージの差分」が対象のため、今回は同じ観点で全体を手作業で調べた。`/security-review` は、これからの PR の差分に使う。

### 調べた項目と結果
| 観点 | 調べたこと | 結果 |
|---|---|---|
| 画面への悪意のある文字の埋め込み（XSS） | `dangerouslySetInnerHTML`・`innerHTML`・`eval`・`new Function`・`document.write` の有無 | **使っていない**。商品名・数量は React が自動で無害化して表示する |
| 入力の検証 | 数量（数字のみ・9 桁まで・0〜999999999）、商品名（50 文字） | 画面側で制限あり。保存値が壊れていても `toValidCount` で 0 にする（テストあり） |
| ブラウザ内の保存 | localStorage の使い方 | キーは 2 つだけ。保存するのは数量と商品名のみで、個人情報・秘密情報は入れていない |
| 外部との通信 | `fetch`・`XMLHttpRequest`・`WebSocket`、外部の URL・スクリプト | **なし**。ブラウザでの確認でも通信 0 件（[品質チェック](quality-review.md)） |
| 秘密情報 | `.gitignore`（`.env`・`*.pem`・`*.key`）、追跡中のファイル、全コミット履歴のキー・トークン検索 | **見つからなかった**。`.env` 類は追跡されていない |
| 実在の個人情報 | ドキュメント・コードのメールアドレス・電話番号・外部 URL | なし（会社名・人名は架空）。コミットのメールは GitHub の noreply アドレス |
| 依存部品 | `npm audit`、`npm outdated` | 脆弱性 0 件、すべて最新 |
| CI（GitHub Actions） | 権限、秘密情報の使用 | `permissions: contents: read` のみ。使う秘密情報（Secrets）は 0 件。リポジトリの既定の権限も `read` で、Actions が PR を承認することも不可 |
| リポジトリ | 公開範囲 | 非公開（PRIVATE） |

### 気をつける点（今は直さない）
| # | 内容 | 影響 | いつやるか |
|---|---|---|---|
| SEC-1 | Actions（`actions/checkout`・`actions/setup-node`）を、バージョン名（タグ）で指定している。タグは後から差し替えられる可能性があり、コミットの ID で固定するほうがより安全 | 小（公式の Actions で、権限は読み取りのみ） | 公開するとき。または Dependabot で自動更新にする |
| SEC-2 | 画面に CSP（Content-Security-Policy。読み込んでよいものを限定するブラウザの設定）などのセキュリティヘッダーがない | 小（外部読み込み・サーバーがないので、今は影響が少ない） | 公開するとき（公開先の設定で付ける） |
| SEC-3 | 非公開から公開にするとき、過去のコミット履歴もすべて見える。今回の検索ではキー・トークンは 0 件だったが、公開の直前にもう一度確認が必要 | 公開時のみ | 公開の直前 |

### 補足（仕様として）
- localStorage は、同じ端末・同じブラウザを使う人なら見られる。共用タブレットで使う場合は、数量が他の人に見えることを前提にする（今回は機密情報ではないため問題なし）。
- main の保護は、このパソコンのフックと設定だけ（[品質チェック](quality-review.md) の I-3）。GitHub 側のルールセットは、無料プランの非公開リポジトリでは使えない。
